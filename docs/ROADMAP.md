# Aktuelle Prioritäten

1. Die konsolidierte content-first Architektur beibehalten: ein vollständiger Prozessbestand, optionale Quellen, einfache offene Punkte und generische Queries.
2. Vorhandene SB02-Schritte anhand tatsächlich verfügbarer Fachinformationen erschließen. Fehlende Materialien sichtbar lassen; keine Bedienwege oder Schulungsreife erfinden.
3. Aktuelle fachliche Grenzen gezielt klären: Rechte-/Bestands-Site-Reichweite, Build-Team-Synchronisation, Start Date/EDC-Geltung, Project-Purpose-/WBS-Meldungen sowie begrenzter R1-Status-/Reportingweg.
4. Neue Releases und Schulungsblöcke ausschließlich im generischen Modell ergänzen. Materialgültigkeit für jedes Release fachlich prüfen.
5. Inhaltspflege anhand realer Autorenarbeit verbessern. Neue Artikel können bereits als einfache JSON-Dateien ergänzt werden; ein zusätzlicher „Artikel anlegen“-Formularweg ist optional.
6. Suchqualität und Orientierung mit Anwendern prüfen. Einen generierten SQLite-Suchindex nur bei gemessenem Bedarf erneut bewerten; JSON bleibt der kanonische Bestand.

Historische Releasepläne und Pflegefälle liegen unter `docs/archive/`. Sie bestimmen weder das heutige Datenmodell noch aktuelle Freigaben. Release, Merge und Veröffentlichung sind gesonderte Entscheidungen.
